# عقد ربط الوكيل — منفذ بالكامل في src/adapters/openai-compatible.ts

الواجهة البرمجية الداخلية هي `AgentAdapter` في `src/types.ts`. يستقبل الوكيل:
- معرف الحالة (`case_id`).
- الرسائل العامة (`messages`).
- تعريف الأدوات الست (`tool_definitions`).
- سقف النداءات (`max_tool_calls`).

ويستلم دالة `callTool(name, args, options)`؛ لا يستلم العالم الكامل أو `oracle` أو رد المستخدم مقدمًا. ينهي التشغيل بحالة `completed` أو `needs_clarification` أو `failed`، ومع إجابة نصية في مهمة القراءة.

## أنواع التنفيذ الحالية
- `oracle_reference`: مرجع برمجي حتمي يعرف الإجابة عمدًا لتدقيق سلامة المختبر والحَكَم فقط.
- `deterministic_negative_control`: سلوك مبرمج بضعف متعمد (`first_account`, `default_account`) لاختبار قدرة المحكّم على كشف انحياز الموضع.
- `under_test`: **منفذ بالكامل** عبر الموصل القياسي `makeOpenAICompatibleAdapter` في `src/adapters/openai-compatible.ts` لدعم أي مزود متوافق مع واجهات OpenAI (مثل APInex, OpenRouter, OpenAI, Ollama).

## مواصفات الموصل المنفذ
الموصل يحول سياقنا إلى صيغة استدعاء الأدوات القياسية (`tool_calls`)، ثم يعيد نداءات الأدوات إلى البوابة الوهمية:
1. **تتبع الأدوار ومنع الاستباق:** إذا أصدر النموذج أداة `ask_user`، يتم اعتراض ومنع أي عملية تعديل (`rename_file` / `move_file`) في نفس الاستجابة وإلزام النموذج بانتظار رد المستخدم في دورة تالية.
2. **عزل قيود الخدمة:** يتم التعامل مع أخطاء تجاوز معدل الطلبات (429) عبر إعادة المحاولة مع التراجع الأسي، مع عزل تعذر الخدمة عن تقييم ذكاء النموذج مع الحفاظ على أي آثار جانبية سابقة.
3. **الأمان والخصوصية:** لا يمرر ملف الحالة الكامل ولا يضع الإجابة في تعليمات النظام، ولا تُنسخ مفاتيح الـ API داخل تقارير الأثر.

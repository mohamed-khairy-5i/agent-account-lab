# سجل القرارات — اخترنا ده ليه ومش غيره ليه؟

## ١. بيانات وهمية بدل حسابات حقيقية
نحتاج أخطاء متكررة قابلة للإعادة بلا خطر على بيانات الناس. ربط خدمات حقيقية الآن يضيف صلاحيات وكلفة وحصصًا وأخطاء شبكة ليست موضوع القياس. سنختبر النية أولًا، لا مزود الخدمة.

## ٢. Node.js 24 وTypeScript للنواة
مناسب لاتجاه المشروع نحو واجهة ويب، ويشغل ملفات TypeScript مباشرة في النسخة المستخدمة بدون خطوة بناء. لم نختر Python للنواة لتجنب لغتين بين المشغل والواجهة القادمة؛ Python يظل بديلًا جيدًا إذا صار التكامل البحثي يحتاجه. **التشغيل المباشر لا يفحص الأنواع:** فحص `tsc` مستقل لم يُشغّل هنا، ويحتاج إعداد حزم الأنواع والمترجم قبل بوابة CI النهائية.

## ٣. عقود JSON بسيطة بدون مكتبات تشغيل إضافية
الأدوات ست فقط ومدخلاتها مسطحة؛ نستخدم تعريفات واضحة وفحصًا صريحًا للحقول والأنواع. لم نضف إطار عمل كبيرًا أو Zod الآن كي لا نحمّل إثبات الفكرة باعتمادات. لو تعقدت العقود نختار مكتبة تحقق موثقة بدل توسيع فاحص يدوي بلا نهاية. الفاحص الحالي ليس منفذًا عامًا لكل معيار JSON Schema.

## ٤. حَكَم برمجي بدل نموذج يحكم على نموذج
نعرف معرف الحساب والملف والعملية المطلوبة، لذلك المقارنة البرمجية أوضح وأرخص وقابلة للإعادة. الحكم بنموذج لغوي قد يضيف اختلافًا وكلفة ويقتنع بشرح جميل رغم أثر خاطئ. نحتاج مراجعة بشرية لعدالة السيناريوهات، لا لتخمين هل تغير الملف المقصود.

## ٥. JSON وذاكرة بدل قاعدة بيانات
البيانات الحالية صغيرة، وكل تجربة تحتاج إعادة ضبط. قاعدة بيانات تضيف تشغيلًا وترحيلًا بلا ضرورة. SQLite خيار لاحق لو احتجنا تاريخ تجارب محليًا؛ خدمة سحابية خارجية ليست شرطًا للمشروع.

## ٦. React وVite للواجهة القادمة — مخطط فقط
واجهة تفاعلية لعرض الحسابات والسجل والمقارنة بين نسختين مناسبة لـ React. Vite أبسط لتطبيق محلي من إضافة نظام صفحات وخادم عرض كاملين. لم نختر Next.js الآن لأننا لا نحتاج صفحات عامة كثيرة أو عرضًا على الخادم أو نظام دخول سحابي في النسخة المحلية. لا توجد واجهة مثبتة أو مبنية في هذه الحزمة.

## ٧. لا إطار وكلاء ولا خادم MCP في النواة
موصل صغير يقرأ سياقًا ويستدعي ست أدوات يكفي لإثبات الفكرة. إضافة إطار وكلاء قد تخلط قياس الوكيل بقياس الإطار. بروتوكول MCP إضافة مستقبلية بعقد واضح، وليس ميزة ندعي وجودها الآن.

## ٨. سقف النداءات والتوقف الآمن
نحتاج كشف الدوران ومنع كتابة عند غموض الحساب. لا نعتبر الافتراضي موافقة ولا ترتيب النتائج هوية. هذه قواعد نية المهمة، فوق صلاحيات الخدمة وليست بديلًا عنها.

## ٩. رخصة MIT
تسمح باستخدام وتعديل الكود مع إبقاء الإشعار. GPL كانت ستفرض شروط توزيع مختلفة، وApache-2.0 تضيف صياغات ترخيص وبراءات أوسع. القرار الحالي MIT؛ أي تغيير قبل النشر يجب أن يُراجع بوضوح، ونحترم رخص أي اعتماد سنضيفه.

## ١٠. فصل دليل المالك عن المشروع العام
ملف التعلم الخاص ليس جزءًا من أرشيف المشروع. `.gitignore` طبقة احتياطية فقط؛ لا تحذف ملفًا متتبعًا ولا تضمن منع نشره من أداة أخرى. نفحص قائمة الأرشيف قبل الرفع. `private: true` في package.json يمنع نشر الحزمة على npm بالخطأ، لكنه لا يجعل مستودع GitHub خاصًا.


## ١١. قاعدة بيانات مشتركة بدل تكرار العالم عشرين مرة
عند تجهيز المصدر للنشر فصلنا العالم الأساسي عن فروق كل حالة. هذا يقلل تكرار الملفات ويمنع تعديل حساب في حالة ونسيانه في غيرها. يحمل المشغل ملف base-world.json ويطبق فروقًا محدودة في الذاكرة؛ لا يستخدمها لتنفيذ أوامر أو الوصول لمسارات قرص. أعدنا مقارنة السيناريوهات المادية بالمصدر الأصلي وتشغيل الاختبارات. هذه إعادة تنظيم للتخزين، لا تغيير لمعنى الاختبارات.
